# Decisions (ADR-lite)

Append new entries at the bottom. Format: context → decision → consequences.

## ADR-001 Build from scratch instead of forking pg-view
pg-view has no public source repository (only a Docker image), no user model and
no SSO. Requirements (Entra SSO, cluster discovery, per-group authz, audit) touch
every layer. → Build our own; pg-view is the functional reference only.

## ADR-002 Go backend + React SPA in one binary
Team strength is Go; single static binary simplifies deployment and image
hardening. SPA embedded via `go:embed`. No SSR.

## ADR-003 SQLite (modernc) as app store, single replica
Store holds sessions, history, favorites, drafts, ui state, audit. Volume is
small. SQLite avoids an extra dependency inside the cluster and keeps the app
self-contained. → `replicas: 1`, `Recreate` strategy, PVC.
Consequence: no HA; brief downtime on upgrades. Audit is also shipped to stdout
so loss of the PVC does not lose the audit trail. A Postgres store backend can be
added later behind the `store.Store` interface (keep it an interface from day 1).

## ADR-004 Fetch all results in Postgres TEXT format
Avoids per-type JSON mapping bugs (numeric precision, int8 > 2^53, intervals,
ranges, composite, custom enums, arrays). UI shows exactly what psql shows.
Writes send text and cast server-side with `$n::<format_type>`.
Consequence: no client-side numeric sorting of results (grid sorting is
server-side anyway).

## ADR-005 Secrets: `get` only, no list/watch
Listing/watching Secrets would load every secret of target namespaces into
memory. Discovery only needs names (from pod specs/CR conventions); values are
fetched by `GET` at pool creation. RBAC grants `get` on secrets only.

## ADR-006 Explicit namespace list, no cluster-wide discovery
Least privilege and predictable blast radius. Namespaced Roles generated by the
Helm chart per listed namespace. No ClusterRole for workloads/secrets.

## ADR-007 No Microsoft Graph in v1
Groups taken from the ID token only; overage rejected with instructions to use
`ApplicationGroup` claims. Avoids Graph permissions/consent. Revisit if needed.

## ADR-008 Statement classification with libpg_query (wasm, pure Go)
Regex-based detection of destructive SQL is unreliable (CTEs, comments,
quoting). `github.com/wasilibs/go-pgquery` gives the real Postgres parser
without cgo.

## ADR-009 One statement per editor execution
Simplifies classification, confirmation, cancel, result shaping and audit.
Multi-statement scripts are a possible v2 feature.

## ADR-010 Authorization in the app, plus optional read-only DB role
Discovered credentials are usually owner/superuser. App-level rules + READ ONLY
transactions are the baseline; a dedicated read-only Postgres role referenced
via annotation is the recommended hardening for production targets.
